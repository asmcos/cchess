> 项目：`/Users/klang/chess/chess_book` ｜ 运行端口：`8945`
> 启动：`python3 server.py 8945` ｜ 访问：`http://127.0.0.1:8945/`

---

## 1. 项目概述

本项目是一个**本地中国象棋棋谱（XQF）Web 浏览器**，用于在浏览器里浏览、检索、分类和打谱海量棋谱（全库约 8557 个 .xqf 文件）。

核心能力：

- **棋谱库视图**：按项目原有目录结构浏览全部棋谱，点选即加载到 SVG 棋盘打谱。
- **开局过滤**：按一级开局类型（中炮局 / 飞相局 / 仙人指路……）快速筛出同类棋谱。
- **分类视图**：`一级开局 → 二级体系 → 棋谱` 的三级分类树，点二级列出该类全部棋谱。
- **智能开局判定**：基于红方第一步 + 前 8 步主变自动识别开局（一级）与黑方应法（二级）。

全程**零额外 pip 依赖**（复用项目既有 `cchess` 解析逻辑 + Python 标准库），前端无框架（原生 JS + SVG）。

## 3. 整体架构与数据流

```
                     ┌──────────────────────────────┐
 浏览器 (web/*)      │       server.py (8945)        │
                     │                              │
  ┌───────────┐      │  /api/tree   → build_tree()  │──扫描目录──► .xqf 文件
  │ 棋谱库视图 │─────►│  /api/index  → 读 index.json │◄─build_index.py 预生成
  │ 分类视图  │      │  /api/game   → cchess 解析    │──读单局──► cchess.Game
  │ 开局过滤  │◄─────│  静态: / → web/index.html     │
  └───────────┘      └──────────────────────────────┘
                              ▲
                    index.json（build_index.py 产出）
```

数据流说明：

1. **启动**：`server.py` 提供 3 个数据 API + 静态前端，本身不做耗时的全库扫描。
2. **索引预生成**：`build_index.py` 一次性扫描全库，为每局判定一级/二级开局，写入 `index.json`（约 1.9MB）。`/api/index` 直接读文件返回，避免每次请求都解析全库。
3. **浏览**：前端首屏并发请求 `/api/tree`（目录树）和 `/api/index`（开局索引），据此渲染两大视图。
4. **打谱**：点任一棋谱 → `GET /api/game?path=<相对路径>` → 服务端用 `cchess` 解析该局为 JSON → 前端渲染到 SVG 棋盘并支持步进播放。

## 4. 后端服务 `server.py`

### 4.1 目录分类（`list_book_roots`）
保持与既有 `a.py` 的 `list_books` 一致的顶层分类：
`比赛对局 / 布局 / 大师专集 / 近代国手名局 / 让子局 / 实战中局夺子取胜技巧150局 / 未分类`；
`残局 / 全局` 两组下**每个子目录视为一本书**。

### 4.2 棋谱解析（`parse_game_to_json`）
- 读 `cchess.Game`，把 90 格棋盘转为一维数组 `row*9+col`。
- **上下翻转**：`cchess` 的 `init_board` 行 0 是红方，传统视角"红在下、黑在上"，故统一翻转（`flp = (9-r)*9+c`）。
- 每步着法打包为 **32bit int**（`who<<30 | src<<22 | des<<14 | src_chess<<7 | des_chess`），与 `a.py` 序列化格式兼容。
- **迭代栈遍历 + seen 环检测**：用显式栈替代递归，规避深链棋谱触发 Python 递归上限；`seen` 集合防止循环引用棋谱（如《三军用命.XQF》）死循环。
- 输出 JSON：`{start, moves[], comment, parent, winner, info, title}`。

### 4.3 API

| 路径 | 说明 |
|---|---|
| `GET /` | 返回 `web/index.html` |
| `GET /api/tree` | 目录树 `{label, path|children}`，文件夹在前按名排序 |
| `GET /api/index` | 读 `index.json`（含 `openings`、`games[]`、统计）。未生成则提示先跑 `build_index.py` |
| `GET /api/game?path=<相对路径>` | 解析单局 JSON；`unquote_plus` 处理空格/`+`；校验路径防目录穿越 |

### 4.4 安全
`/api/game` 的 `path` 经 `os.path.normpath` + `startswith(ROOT)` 校验，拒绝目录穿越。

## 5. 开局分类体系 `openings.py`

### 5.1 坐标与棋子编码
- 一维下标 `row*9+col`；`_flp` 上下翻转（`cchess` 行0为红，标准视角红在下）。
- 红视角列：`col0=九路 … col8=一路`。
- 棋子：红 `1车 2马 3相 4仕 5帅 6炮 7兵`，黑 `8车 9马 10象 11士 12将 13炮 14卒`。

### 5.2 一级开局 `detect_opening`
只看**红第一步**的兵种与落点：

| 红第一步 | 一级 |
|---|---|
| 炮平五路（中路，des_col=4） | 中炮局 |
| 炮平六路（des_col=3） | 过宫炮局 |
| 炮平四路（士角，des_col=5） | 仕角炮局 |
| 其它炮 | 其它炮局 |
| 马 | 起马局 |
| 兵 | 仙人指路 |
| 相 | 飞相局 |
| 士 | 上士局 |
| 其它 | 其它开局 |
| 无着法 | 无着法 |

### 5.3 二级开局 `detect_opening2`
`一级 + 对黑方应法`，黑方应法由**前 8 步主变**（`mainline_moves(game,8)`，每层取第一个子着法）判定：

- **中炮局**（`_detect_zhongpao`）：
  - 红体系：红第 2 步进三兵/进七兵 → 前缀"进三兵/进七兵"。
  - 黑应法：炮平中且左炮=顺炮、右炮平中=列炮、炮平士角=反宫马；黑马正马位（des_col∈{2,6}）再看第二只马是否也正马 → 屏风马（否则单提马）；黑卒=卒底、黑车=对车。
  - 命名例：`中炮进三兵对屏风马`、`中炮对顺炮`。
- **非中炮一级**（通用）：`{一级}对{黑第一步应法}`，由 `_black_first_reply` 给出黑应法名（左/右中炮、士角炮、屏风马、单提马、挺卒、飞相、上士、车……）。
  - **特例**：仙人指路（红挺兵）后黑挺卒 → 标准叫法 `仙人指路对卒底炮`。
- **残局/排局**（`info.type ∈ {2,3}`）不判开局，二级记为 `残局`。

### 5.4 关键修正（经验）
1. 黑马正马位是**黑视角** `des_col ∈ {2,6}`（不是中间列 4）。
2. 屏风马须看**前 8 步**：第二只马常在第 3 步才跳，只看前 4~6 步会误判为单提马。
3. 残局/杀法棋谱（如"炮高兵巧胜单士象"）不得误归中炮局——用 `info.type` 前置拦截。

## 6. 索引构建 `build_index.py`

### 6.1 策略：多进程并行 + 卡死防护
- **fork 多进程**（`N_WORKERS = min(8, cpu)`）：子进程继承解释器，比 subprocess 快。
- **单棋谱强超时**：每局在独立子进程解析，超过 `TIMEOUT=8s` 由父进程 `terminate` 跳过并记 `fail`——**绝不因个别卡死棋谱拖垮整个构建**（这是早期 `SIGALRM` 单线程方案不可靠后改为的方案）。
- 结果经 `multiprocessing.Queue` 回传父进程聚合。

### 6.2 输出 `index.json`
```json
{
  "version": 1,
  "openings": ["中炮局", ...],           // 一级类型清单
  "games": [                             // 每局一条
    { "path": "...", "name": "...", "opening": "中炮局",
      "opening2": "中炮对屏风马", "red": "...", "black": "...",
      "event": "...", "result": "..." }
  ],
  "count": 8538, "fail": 19, "timeout": 19, "build_seconds": 708.8
}
```

### 6.3 实测结果
全库 8557 个 XQF，成功 **8538**，**19 个卡死跳过**（约 0.2%），耗时约 **708s**。
一级分布：中炮局 3749、仙人指路 1311、起马局 678、飞相局 506、其它开局 1658、其它炮局 284、过宫炮局 146、仕角炮局 141、上士局 51、无着法 14。

## 7. 前端 `web/`

原生 JS + SVG，无框架。两大视图由顶部 tab 切换（`棋谱库 / 分类`）。

### 7.1 棋盘渲染
- `gridHTML()`：SVG 画棋盘（横竖线、九宫斜线、楚河汉界、边框）。
- `renderPieces()`：按一维数组 `board[]` 画子（红 `#fdfdf6`、黑 `#26221b`）。
- 打谱：`loadGame(path)` 拉 `/api/game` → 重建初始局面 + 着法 → 步进播放（前后步 / 首末 / 自动播放 / 键盘方向键）。

### 7.2 棋谱库视图 + 开局过滤
- `loadTree()`：并发拉 `/api/tree` 和 `/api/index`，构建目录树与 `openingMap`、`countByOpening`。
- 开局过滤下拉：选一级 → `filterTree()` 只保留匹配该开局的棋谱节点，并显示各分类计数。
- **双标题**：节点主标题显示**文件名**（便于用户按文件名分类），棋谱内标题用黄色小字单独显示。

### 7.3 分类视图
- `renderCatTree()`：由 `index.games` 的 `opening`（一级）+ `opening2`（二级）聚合为分类树，按 `ORDER1` 排序，节点带计数。
- `showCatGames(l1, l2)`：点二级 → 在 `#catList` 列出该类全部棋谱（含红黑对局信息）。
- 点棋谱 → 复用 `loadGame()` 加载到棋盘。
- 数据全部来自 `index.json`（一次加载进内存），无额外 API 调用。

## 9. 已知限制与后续方向

- **卡死棋谱**：19 个解析超时被跳过（约 0.2%），可单独排查修复其 XQF 结构。
- **二级细分**：部分二级"对其它"占比偏高（如仙人指路对炮 380、起马对其它 237），可继续细分（对炮/对车等）。
- **性能**：索引为预生成（708s），运行时零扫描；若棋谱增量更新，需重跑 `build_index.py`。
- **可能的增强**：每个二级补充开局讲解/定式；分类视图一级过滤下拉；索引增量构建。
